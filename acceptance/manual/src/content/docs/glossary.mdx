The words this manual leans on, grouped by what they belong to. GemStone borrows a
few common terms (image, repository, package) for specific meanings — those are
the ones worth pinning down.

## The database and its server

**Stone**
: The GemStone repository-monitor process — the server that manages the database.
  "The stone" is usually shorthand for the running database itself.

**Database** (repository)
: The persistent store of objects the stone manages. On disk it is one or more
  *extent* files; in memory it is the *image*.

**Extent**
: The file(s) on disk that hold the database's objects (e.g. `extent0.dbf`). A new
  database is created by copying a shipped extent — a **rowan3** extent, for
  instance, comes with Rowan already loaded.

**Image**
: The live world of objects — every class and instance — as it exists in the
  running stone. Code you compile lives in the image; *committing* makes it
  permanent.

**Transaction**
: The unit of committing or aborting. Changes you make are private until you
  **commit** the transaction, which persists them to the database.

**Disk**
: The on-disk *source* form of code — Tonel files in a Rowan project — as opposed
  to the image. "Disk-first" authoring edits the files and loads them into an
  image; the image and disk can *drift* until reconciled.

## Connecting

**Session**
: One live login to a stone — the context your code runs in. Ends when you log
  out.

**Gem**
: The GemStone process that executes Smalltalk for a session (one gem per
  session).

**NetLDI**
: The GemStone network server that brokers connections and spawns gems for
  logins. Jasper connects to it by host and port.

**GCI**
: The GemStone C Interface — the native library Jasper uses to drive a session.

## Users

**DataCurator**
: The default data-owning user account. Jasper connects as DataCurator by
  default; everyday work — browsing, executing, authoring in your own namespace —
  is done as a normal user like this.

**SystemUser**
: The superuser that owns the kernel classes and Rowan's system registry. It is
  used only for genuinely system-level operations (and Jasper avoids it
  otherwise) because it runs with full privilege.

**Symbol dictionary**
: A namespace in the image mapping names to classes and globals (e.g.
  `UserGlobals`, `Globals`). Your *symbol list* is the ordered chain of
  dictionaries searched to resolve a name.

## Code, on disk (Rowan)

**Rowan**
: GemStone's system for managing code as disk-based source — keeping Tonel files
  and the image in sync, and loading projects into a stone.

**Project**
: The top-level Rowan unit on disk: a folder with a `rowan/project.ston` manifest
  that groups packages, components, and load specifications.

**Package**
: A Rowan unit grouping related classes and methods — on disk, a directory of
  Tonel class files.

**Component**
: A named grouping of packages within a project — a load unit you can include or
  leave out.

**Load specification** (load spec)
: A Rowan spec that names which components and packages to load, plus platform
  settings, when a project is loaded into an image.

**Repo** (repository)
: Overloaded, so watch context: the GemStone *repository* is the database; a
  Rowan *repository* is a source checkout of a project's Tonel files on disk. In
  Jasper's Rowan view, "repo" means the latter.

**Class category / method category**
: Organizational labels. Classes are grouped by *class category*; a class's
  methods are grouped by *method category* (their protocol).

## File formats and tools

**Tonel**
: A plain-text, git-friendly format for Smalltalk source — one file per class,
  holding its definition and methods. Rowan packages are stored as Tonel.

**STON**
: Smalltalk Object Notation — a JSON-like text format. Rowan's project and load
  specifications are STON files (`.ston`); Jasper edits them in a settings editor.

**Topaz**
: GemStone's command-line tool for scripting a stone (`.gs` / `.tpz` scripts).
